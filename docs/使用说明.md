# ImmortalWrt Builder — 构建说明

## 概述

基于 GitHub Actions 的 ImmortalWrt x86_64 固件自动构建，支持自定义分支/tag。所有包从 ImmortalWrt 官方源码编译。

---

## 工作流

`.github/workflows/build.yml` — 由 `workflow_dispatch` 触发，三个输入参数：

| 参数 | 说明 | 默认值 |
|------|------|--------|
| `repo_branch` | ImmortalWrt 分支或 tag | `master` |
| `rootfs_size` | Rootfs 分区大小（MB） | `4096` |
| `include_docker` | 是否启用 Docker | `yes` |

**步骤序列：**
1. 准备环境（apt 依赖、磁盘清理、swap）
2. 检出 builder 仓库 + git clone ImmortalWrt 源码
3. 恢复 dl 缓存 / ccache 缓存
4. `bash diy-part1.sh` — 配置 feeds
5. `bash diy-part2.sh` — 核心配置编排（见下文）
6. `make download -j$(nproc)` — 下载源码
7. 保存 dl 缓存 / 保存/恢复 ccache 缓存
8. `make -j2 V=1 CONFIG_CCACHE=y CONFIG_CCACHE_DIR="/home/runner/.ccache"` — 编译
9. ccache 统计 + 超 6GB 自动清理
10. `gh release create` — 发布固件到 GitHub Releases（保留最新 3 个）

---

## 核心脚本

### `diy-part1.sh` — Feed 配置

**接口：** 无参数，需要 CWD = `/workdir/openwrt`。

**流程：**
```
feeds update -a
feeds install -a
```

如需第三方 feed，取消注释 `src-git kenzo ...` 行。

---

### `diy-part2.sh` — 自定义配置编排

**接口：** 需要 CWD = `/workdir/openwrt`，读取环境变量 `ROOTFS_SIZE` 和 `INCLUDE_DOCKER`。

**流程：**
1. 下载 Linux 官方 `scripts/config` 为 `kconfig-tool`
2. 注入 32 位运行时库（`scripts/runtime-musl32.sh` + `runtime-glibc32.sh`，存在则执行）
3. 写入种子 `.config`（`CONFIG_TARGET_x86=y` + `CONFIG_TARGET_x86_64=y`）
4. `make defconfig` 展开完整配置
5. `bash scripts/kernel-config.sh` 注入内核补丁
6. `python3 scripts/kernel-config-patch.py` 注入 olddefconfig
7. 启用 CCACHE：`--enable CONFIG_CCACHE` + `--set-str CONFIG_CCACHE_DIR`
8. 设置 rootfs 大小（读取 `$ROOTFS_SIZE`）
9. `make olddefconfig` 解决内核依赖

**约束：** 第 7 步之后**绝不可再执行** `make defconfig`（会重置 CCACHE 设置）。

---

### `scripts/kernel-config.sh` — 内核配置

**接口：** 需要 CWD = `/workdir/openwrt`，读取环境变量 `INCLUDE_DOCKER`。

**功能：**
- 自动探测 `target/linux/x86/64/config-*` 内核配置文件
- 始终追加 `CONFIG_IA32_EMULATION=y`
- 当 `INCLUDE_DOCKER=yes` 时追加 Docker 内核模块（VETH、MACVLAN、IPVLAN、VXLAN、IP_VS、CGROUP 等）

---

### `scripts/kernel-config-patch.py` — 编译期 olddefconfig

**接口：** `python3 scripts/kernel-config-patch.py <kernel-defaults.mk 路径>`。

**功能：** 在 `include/kernel-defaults.mk` 的 vermagic 行后注入 `$(KERNEL_MAKE) olddefconfig`，防止内核版本升级引入的新选项导致 `syncconfig exit 2`。

---

### `scripts/runtime-musl32.sh` — 32 位 Musl 运行时

从 `runtime/musl32.tar.gz` 解压 32 位 musl 库到 `files/`。tarball 包含：`ld-musl-i386.so.1`、`libatomic`、`libgcc_s`、`libstdc++`、`libssl`、`libcrypto`、`libcurl`、`libz`。

### `scripts/runtime-glibc32.sh` — 32 位 Glibc 运行时

优先从 `runtime/glibc32.tar.gz` 解压，失败则从 runner 系统路径在线提取。包含 `ld-linux.so.2`、`libc.so.6`、`libpthread`、NSS 库等。

### `files/usr/bin/run-i386` — 32 位 ELF 调度器

**用法：** `run-i386 <binary> [args...]`。自动识别 musl/glibc 二进制并设置正确 `LD_LIBRARY_PATH`。

## 缓存策略

### dl 缓存
```
Restore:  dl-{branch}-{date}-{hash(diy-part1.sh,scripts/kernel-config.sh)}-
           └─ 精确匹配 → 当日回退 → 全量回退
Save:     dl-{branch}-{date}-{hash}-run_{run_id}  （每次构建独立条目）
```

### ccache 缓存
```
Restore:  ccache-{branch}-{date}-
           └─ 当日回退 → 全量回退
Save:     ccache-{branch}-{date}-run_{run_id}
```

编译命令通过 `CONFIG_CCACHE=y CONFIG_CCACHE_DIR="/home/runner/.ccache"` 强锁路径。**`/home/runner/.ccache` 不可改为 `~` 或 `$HOME`**，否则缓存版本计算不一致。

---

## Docker 支持

| 类别 | 内核选项 |
|------|----------|
| 网络虚拟化 | VETH, MACVLAN, IPVLAN, VXLAN |
| Netfilter | NETFILTER_XT_MATCH_ADDRTYPE, IP_VS, IP_VS_RR |
| Cgroup | CGROUP_PIDS, MEMCG |

---

## 32 位应用支持

- 内核 `CONFIG_IA32_EMULATION=y`
- 双运行时 musl + glibc，预置到固件中
- `run-i386` 调度器自动选择正确运行时
- 升级 ImmortalWrt 版本时需重新生成 `runtime/*.tar.gz`

---

## 维护注意事项

1. **`kconfig-tool` 启用 CCACHE 后绝不再执行 `make defconfig`** — 用 `make olddefconfig` 代替
2. **CCACHE 路径硬编码不可改** — `/home/runner/.ccache` 在 actions/cache 和 make 参数中必须一致
3. **第三方 feeds 在 `diy-part1.sh` 中添加** — feeds update 之前写入 `feeds.conf.default`
4. **强制启用包在 `diy-part2.sh` 中取消注释** — 例如 `CONFIG_PACKAGE_docker`
5. **死代码已清理** — `shell/prepare-store.sh`、`scripts/sort-ipk-deps.py` 已删除
