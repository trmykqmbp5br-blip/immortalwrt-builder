# ImmortalWrt Builder — 构建说明

## 概述

基于 GitHub Actions 的 ImmortalWrt 24.10.6 x86_64 固件自动构建。所有包均从 ImmortalWrt 官方源码编译，无预编译 ipk 注入。

## 工作流步骤

```
1. Prepare environment     # 安装依赖、释放磁盘、创建 swap
2. Checkout                # 检出 builder 仓库
3. Clone source code       # git clone ImmortalWrt v24.10.6
4. Get date for cache key  # 用于 dl/ccache 缓存 key（每天一份）
5. Restore dl cache        # 恢复下载缓存到 /workdir/openwrt/dl/
6. Configure feeds         # diy-part1.sh：feeds update / install
7. Apply custom config     # diy-part2.sh：kconfig-tool → 运行时 → kernel-config → defconfig → CCACHE
8. Download sources        # make download -j$(nproc)
9. Save dl cache           # 成功时保存（含 run_id，每次独立）
10. Restore ccache         # 恢复编译缓存到 /home/runner/.ccache/
11. Compile firmware       # make -j2 V=1 CONFIG_CCACHE=y CONFIG_CCACHE_DIR=...
12. ccache stats           # ccache -s + 超 6GB 清理
13. Save ccache            # 成功/失败分别保存
14. Release firmware       # 上传 img.gz + sysupgrade.bin.gz，保留 3 个
```

## 核心脚本

| 文件 | 作用 |
|------|------|
| `diy-part1.sh` | 配置 feeds 源，执行 feeds update/install |
| `diy-part2.sh` | 下载 kconfig-tool → 32 位运行时 → kernel-config → defconfig → 启用 CCACHE |
| `scripts/kernel-config.sh` | 内核补丁（IA32_EMULATION + Docker 内核依赖 + olddefconfig） |
| `scripts/kernel-config-patch.py` | 在 kernel-defaults.mk 中注入 olddefconfig 步骤 |
| `scripts/runtime-musl32.sh` | 注入 musl 32 位运行时库 |
| `scripts/runtime-glibc32.sh` | 注入 glibc 32 位运行时库 |

## 缓存策略

### dl 缓存

```yaml
# key 含日期 + feeds 配置哈希，每天一份
# save 时追加 run_id，确保每次构建写入独立缓存条目
key: dl-${{ env.REPO_BRANCH }}-${{ steps.cache-date.outputs.date }}-${{ hashFiles('diy-part1.sh', 'diy-part2.sh', 'scripts/kernel-config.sh') }}
restore-keys: |
  dl-${{ env.REPO_BRANCH }}-${{ steps.cache-date.outputs.date }}-
  dl-${{ env.REPO_BRANCH }}-
```

- 恢复时先精确匹配当天哈希，再回退到当天任意版本，最后回退到最近分支缓存
- 成功保存时带 `run_id`，每次构建独立条目，互不覆盖

### ccache 缓存

```yaml
# 同日期格式，save 含 run_id
key: ccache-${{ env.REPO_BRANCH }}-${{ steps.cache-date.outputs.date }}-
restore-keys: |
  ccache-${{ env.REPO_BRANCH }}-${{ steps.cache-date.outputs.date }}-
  ccache-${{ env.REPO_BRANCH }}-
```

- 编译命令通过 `CONFIG_CCACHE=y CONFIG_CCACHE_DIR="/home/runner/.ccache"` 参数强锁
- 确保 OpenWrt `rules.mk` 中 export 的 `CCACHE_DIR` 与 cache action 路径一致
- 编译前执行 `ccache -z` 重置统计 + `ccache -M 5G` 限制容量

## 32 位应用支持

- 内核 `CONFIG_IA32_EMULATION=y`
- 预置 musl 32-bit 和 glibc 32-bit 双运行时
- `files/usr/bin/run-i386` 自动识别 musl/glibc 二进制，设置正确的 `LD_LIBRARY_PATH`

运行时维护：
- `scripts/runtime-musl32.sh` 和 `scripts/runtime-glibc32.sh` 在 diy-part2.sh 中自动执行
- 升级 ImmortalWrt 版本需重新生成 tarball

## Docker 支持

Docker 必需的内核模块在 `scripts/kernel-config.sh` 中通过 kconfig-tool 强制启用：

| 类别 | 选项 |
|------|------|
| 网络虚拟化 | VETH, MACVLAN, IPVLAN, VXLAN |
| Netfilter | NETFILTER_XT_MATCH_ADDRTYPE, NETFILTER_XT_MATCH_IPVS, IP_VS, IP_VS_RR |
| Cgroup | CGROUP_PIDS, MEMCG |

## 维护注意事项

### 编译命令强锁 CCACHE

```bash
make -j2 V=1 CONFIG_CCACHE=y CONFIG_CCACHE_DIR="/home/runner/.ccache"
```

`CONFIG_CCACHE_DIR` 直接传给 make，覆盖 .config 中所有可能的值，确保 rules.mk export 的路径与 cache action 保存的 `/home/runner/.ccache` 一致。此路径不可改为 `~` 或 `$HOME`，否则缓存版本计算不一致。

### 绝对不要在 kconfig-tool 操作之后执行 make defconfig

diy-part2.sh 中 kconfig-tool 启用 CCACHE 后，**绝不可再执行 make defconfig**。defconfig 可能重置 .config 中的值。如有需要，可用 `make olddefconfig`（仅填充新选项默认值，不覆盖已有值）。
